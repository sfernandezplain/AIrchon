**Reading time:** ~22 min

> What this page is: the Copilot-CLI-specific cross-section -- how GitHub's CLI-installed agent answers every mechanism the book taught generally. Where a Copilot CLI docs page turned out to be generic platform guidance rather than CLI-specific, or where `copilot-sdk` material was used as a transport-layer source for CLI behaviour, the wiki flags the boundary explicitly and this synthesis preserves that flag.

## One-sentence shape

Copilot CLI is a closed-source CLI installed via `gh`-adjacent channels that the Copilot SDK describes as "the CLI is the orchestrator" -- a transport-layer SDK speaking JSON-RPC to a CLI process that actually runs a tool-use loop of exactly-one-LLM-call-per-turn (mechanical `model -> toolRequests -> execute -> call model again` with no hidden planning call), completing mechanically at `session.idle` (always, ephemeral) and semantically only when the model calls `task_complete` (`session.task_complete`, persisted, with `summary`), with an autopilot-mode synthetic nudge enforcing a two-level completion gate; a `~/.copilot` config layout (with a bounded repo-scope `settings.json`) and MDM settings that cross-read `~/.claude/settings.json` for interop; instruction files (`AGENTS.md`/`copilot-instructions.md`/`CLAUDE.md` plus path-specific `.github/instructions/**/*.instructions.md` -- user-level `~/.copilot/instructions/**/*.instructions.md` -- with deduplication and a lazy-load optimisation for path-specific bodies); a server-side **Copilot Memory** service (repo-level facts with code citations validated against the branch + user-level preferences, each auto-deleted after 28 days, tool-exposed as `store_memory`/`vote_memory` with scope-visible consent prompts and throttled voting, refreshed every 30 minutes); a 95%-trigger background compaction checkpoint system (compaction preserves skills and extended thinking, `/compact` accepts focus instructions, `preCompact` hook exists); session storage in **session databases** under `~/.copilot/` (relocatable via `COPILOT_HOME`, "session SQL" storage with cross-restart resumption, `/resume`/`--continue` plus `/session id` addressing); and a permission-kind vocabulary (shell/write/read/url/memory/MCP-SERVER) over a changelog-confirmed functional tool set with model-conditional `apply_patch` and a curated GitHub MCP server -- with observability and rendering scoped as lower-priority table-stakes layers (changelog-traced `ink`-based mode cycle including an autopilot mode that suppresses rather than bypasses the dialog, and OTel `gen_ai.*` cache attributes).

## Configuration, permissions, hooks, auth, and usage

**Config (VERIFIED, `configuration.md` Section 2):** `~/.copilot` directory layout (user `settings.json`) + repo `.github/copilot/settings.json` (documented as having a bounded key list, not an arbitrary settings passthrough), a 6/7-link documented precedence chain (personal > path-specific > repo-wide > agent > organization -- flagged BEST CURRENT UNDERSTANDING as the source page enumerates GitHub.com/VS Code/Visual Studio surfaces and does not name the CLI itself), plus the changelog-traced structural history (`config.json` to `settings.json` renames at both repo and user scope). Critically, Copilot CLI's own `changelog.md` documents reading `~/.claude/settings.json` as an interop measure -- the one place a Copilot CLI behaviour is explicitly Claude-Code-aware.

**Permissions (VERIFIED, `permissions-and-sandboxing.md` Section 2):** the docs vocabulary is **permission kinds** (shell/write/read/url/memory/MCP-SERVER -- the nouns the permission schema uses), not a single global permission-model name. The functional tool list is changelog-confirmed rather than docs-tabulated: shell/view/web-fetch/search/task tools, `store_memory`/`vote_memory` (see Memory below), model-conditional `apply_patch` for Codex models (paralled to Ch.06's model-routing), and the curated-by-default GitHub MCP server that lands as tools inside the same kind taxonomy. The `Edit` three-gate check from the general tools chapter is not sourced as a Copilot-CLI-specific mechanism on that harness's own `permissions-and-sandboxing` section -- the page scopes it there to Claude Code instead -- so this synthesis does not import it by analogy.

**Hooks (VERIFIED, `hooks-lifecycle-extensibility.md` Section 2 + cross-ref from `agent-loop-implementations.md`):** changelog-verified `agentStop` hook semantics are the documented loop guard -- an `agentStop` hook returning "block" every time no longer loops indefinitely but ends after **8 consecutive blocks**, a bound this book cross-references from [agent-loop-implementations.md](../../references/harnesses/agent-loop-implementations.md) rather than re-derives as a general hook primitive. An `agentStop` entry prefix-named hook catalogue is implicitly referenced throughout `changelog.md` (the page cites the `changelog.md` entries for that hook specifically).

**Auth and usage (VERIFIED, `auth-and-usage-accounting.md` Section 2 + `model-routing-and-selection.md`):** GitHub-identity-linked auth (`GH_TOKEN`/`GITHUB_TOKEN` handling) plus the three enforcement layers where the wiki documents them (Copilot's spend-denominated `maxAiCredits` as the soft cap from [agent-loop-implementations.md](../../references/harnesses/agent-loop-implementations.md) -- checked after a model call, `session_limits_exhausted.requested` -> `completed` hand-off requiring a user decision -- vs. the SDK-level and org-level layers the same `auth-and-usage-accounting` page scopes). Routing includes the **two-system Auto router** for `model: auto` (documented as a router between two systems per turn, not a single model name).

## Loop, memory, context, and transport

**Loop (VERIFIED, `agent-loop-implementations.md` Section 2 -- the most heavily scoped section in the book):** grounding is `github.com/github/copilot-sdk` `docs/features/agent-loop.md` / `session-limits.md` (fetched via `gh api` 2026-08-24), treated as VERIFIED about the CLI's shape **because the SDK doc itself attributes authorship to the CLI** -- "The SDK is a transport layer... The CLI is the orchestrator that runs the agentic tool-use loop" -- while preserving the standing flag that no first-party `docs.github.com`/`github.com/github/copilot-cli` page independently corroborates it this session. A turn is exactly one LLM API call (`assistant.turn_start` to `assistant.turn_end`) carrying the **full conversation history** on every call (same append-to-context shape the book's Ch.02 describes). The loop's natural stop is model-driven -- "The model is the decision-maker for when to stop" -- and two completion signals with different durability follow. `session.idle` (always emitted when the tool-use loop ends, ephemeral -- not persisted, not replayed on resume -- mechanical "agent stopped processing" semantics; the signal `sendAndWait()` blocks on) vs. `session.task_complete` (optional -- requires the model to call a `task_complete` tool -- persisted with `summary`, semantic "model considers the task fulfilled"). **Autopilot mode** (the book's [tui-cli-application-architecture.md](../../references/harnesses/tui-cli-application-architecture.md) cycled-mode wheel -- interactive/plan/autopilot) turns the optional signal into a second gate: if the tool-use loop ends without `task_complete`, the CLI injects a synthetic user message ("You have not yet marked the task as complete... stop planning and start implementing...") read by the model as an ordinary new turn -- the same injection shape OpenCode's `MAX_STEPS_PROMPT` (on a ceiling) and pi's steering queues (on a human nudge) use, here on a *completion-signal-absent* condition.

**Memory and instructions (VERIFIED, `memory-management.md` Section 2 + `instruction-context-budget.md`):** instruction files -- `copilot-instructions.md` / `.github/instructions/**/*.instructions.md` (path-specific, now lazy rather than always-included per a token-saving changelog entry) / `AGENTS.md` / `CLAUDE.md` (reads `CLAUDE.md` too -- verified via two `changelog.md` entries, "Expand @-style imports..." and "Avoid sending duplicate..."), plus user-level `~/.copilot/instructions/**/*.instructions.md`. But the distinguishing mechanism is **Copilot Memory** (VERIFIED, `docs.github.com/en/copilot/concepts/agents/copilot-memory`): repo-level facts (created only by writers with Memory enabled, stored with the repo with code citations validated against the current branch, usable only on that repo, available to any user with repo access) + user-level preferences (from that user's interactions only), each auto-deleted after 28 days unused (timer reset on validated use), surfaced at profile -> Copilot settings -> Features -> Copilot Memory and at repo Settings -> Copilot -> Memory. The CLI surface (`changelog.md`): `store_memory` (`Injec[t] repo memories in the prompt and add memory storage tool` origin entry, plus scope-visible confirmation prompts showing `user` vs. `owner/repo` and timeline entries showing `(for user)`/`(shared with repository collaborators)`), `vote_memory` (throttled per response/interaction), `/memory on|off|show` (persistent), timeline subject/fact/citations, non-hang and warning when the memory backend is unavailable/outside a repo, and the 30-minute refresh ("Refresh memory context after 30 minutes in long-lived sessions"). A separate, experimental cross-session memory (`/chronicle search`, "ask about past work...") is flagged as distinct. Ch.04 documented that a mid-session instruction-file edit's liveness is **unknown** for Copilot CLI (docs silence, and the path-specific full-body-in-system-prompt removal hints at per-turn assembly but is not a reload guarantee); the post-compaction re-inject is similarly unknown (skills-survive is documented, instruction-file-survive post-compaction is not).

**Context operations (VERIFIED, `context-compression.md` + `caching.md` + `session-persistence.md`):** 95%-of-token-limit background compaction checkpoints (the origin entry "Add auto-compaction at 95%... and `/compact` command" matches the docs number exactly), `/compact` with focus instructions, `/context` and `/usage` overviews, OTel `gen_ai.conversation.compacted=true` on chat spans after a successful compaction with a `CompactionPart` summary. Caching: documented TTL/discount split (10%-read-discount, 24h for OpenAI vs. 1h for others) plus OTel cache attributes and a changelog-traced maturation of cache observability; no source-verified breakpoint-placement file in the style of `packages/llm/src/cache-policy.ts` because Copilot CLI's transport layer is not published source.

**Transport and model selection (VERIFIED, `llm-api-contract.md` + `streaming-and-incremental-rendering.md` + `retries.md` + `model-routing-and-selection.md`):** the CLI's transport is GitHub-routed (proxy/billing), which is why the book flags authority-overreach for direct provider-envelope attribution; the streaming page documents buffering/reassembly/pacing at the UI side with a Copilot-CLI-specific performance shape behind a weekly changelog cadence; retries are per-subsystem changelog entries (0.0.389 -> 1.0.66) because the fetched docs page turned out to be general platform guidance.

## Coordination, skills, tools, and MCP

**Coordination (VERIFIED, `orchestration.md` + `handoff-mechanism.md` + `fan-out.md` + `inter-agent-messaging.md`):** the named orchestration unit is `/fleet` with an explicitly named **orchestrator agent** (plus the Copilot SDK's Fleet-mode `todo_deps` runtime flagged as adjacent-surface background). History: changelog traces `orchestration.md` from a changelog-verified parallel tool execution introduction (2025-10-22) that later made its opt-out flag GA-mandatory (2026-02-25), through subagent depth/concurrency limits (introduced then made configurable, then changed defaults), to `/fleet`'s conditional dependency-based parallelism. Handoff is via custom-agent subagents (plus `/delegate` to a cloud agent and VS Code-only `handoffs` ruled out). Inter-agent messaging is a one-directional `subagent.*` lifecycle event stream (envelope-level `agentId`) plus `/fleet` todo-state coordination; peer-to-peer channel absence is flagged UNCONFIRMED-as-absent, not proven.

**Tools and skills (VERIFIED, `built-in-tools.md` + `built-in-skills.md`):** permission kinds plus functional tools as above; no single global permission-model name is sourced as a replacement for the kind vocabulary. No bundled-skill analogue to Claude Code's `disableBundledSkills` set is documented as a fixed every-session skill table; Copilot's forge-generated pipeline and `/chronicle skills review` is the skills surface the wiki documents.

**MCP (VERIFIED, `mcp-integration.md`):** config/transport surface consistent with the MCP spec over GitHub's proxy, documented alongside the CLI's own GitHub-MCP curation as a first-party-enriched client.
