## One-sentence shape

Claude Code is the harness this book's vocabulary was built from -- "harness" itself is its glossary term -- a closed-source terminal product whose docs-verified contract is: a four-scope `settings.json` hierarchy whose permission rules merge rather than override, a two-layer OS-sandboxed Bash gate underneath a per-tool permission-required table with an Edit three-gate check, an ~30-event hook catalogue where only exit code 2 blocks, an SDK-documented while-loop of one-Clauderesponse-plus-tool-execution turns capped by `max_turns` and `max_budget_usd` (subagent spend included), a 200-lines-or-25KB `MEMORY.md` index plus topic files with a `CLAUDE.md`/`~/.claude/rules/` eager/path-scoped instruction tier that survives compaction asymmetrically (root re-injects, path-scoped is lost), a two-phase evict-then-summarize compaction with a thrash guard, a layer-ordered prompt-caching prefix with TTL-by-auth-path and `ENABLE_PROMPT_CACHING_1H` controls, and a bundled-skill set with `disableBundledSkills` -- plus three fan-out/orchestration layers (in-conversation parallel subagents, `claude agents` background sessions, Workflow `agent()`/`pipeline()`), a `SendMessage`+file-mailbox (`~/.claude/teams/{team}/inboxes/{agent}.json`) with structured protocol messages, a six-channel distribution chain with `manifest.json`+GPG signing and a changelog-traced auto-update history, and three OTel-adjacent observability pipes (debug flags, `/context`/`/hooks`/`/mcp` introspection, beta `claude_code.*` traces with `traceparent` propagation) alongside default-on vendor telemetry.

## Configuration, permissions, hooks, auth, and usage

**Config (VERIFIED, `configuration.md` Section 1):** four scopes -- Managed (`/Library/Application Support/ClaudeCode/CLAUDE.md` macOS, `/etc/claude-code/CLAUDE.md` Linux/WSL, `C:\Program Files\ClaudeCode/CLAUDE.md` Windows) / User (`~/.claude/settings.json`) / Project (`.claude/settings.json` or `~/.claude.json` legacy, migrated via CHANGELOG) / Local (`.claude/settings.local.json`) -- with a docs-internal inconsistency flagged on CLI-flags-vs-Managed ordering. The named merge exception: permission rules merge; most other keys are narrowest-wins. `claudeMdExcludes` (glob, arrays merge) and `claudeMd` inlining (managed only) modulate the `CLAUDE.md` discovery this section's companion (Ch.04) documents; `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` gates `--add-dir` memory files.

**Permissions (VERIFIED, `permissions-and-sandboxing.md` Section 1):** the `tools-reference` table is the inventory (`permission-required` as a routing column); the enforcement underneath is a **two-layer OS sandbox for Bash** (filesystem + network, independently documented, with named escape hatches). The Edit three-gate check and Bash timeout/backgrounding are the safety stories with concrete names. Hooks can also block via `PreToolUse` (see below), not via a memory file -- the docs state memory files are "context, not enforced configuration."

**Hooks (VERIFIED, `hooks-lifecycle-extensibility.md` Section 1):** ~30 events (`PreToolUse`, `PostToolUse`, `PreCompact` -- which can block compaction with `exit 2`/`{"decision":"block"}`, `Stop`, `SessionStart`/`SessionEnd`, `UserPromptSubmit`, `TeammateIdle`/`TaskCreated`/`TaskCompleted` with a flagged payload-schema gap, etc.). Rule: **only exit code 2 blocks**; other non-zero exits surface but do not block. Verified via a re-fetched `gh api raw` HTML pass on the hooks page to check the lifecycle location claim directly (2026-09-03).

**Auth and usage (VERIFIED, `auth-and-usage-accounting.md` Section 1 + `retries.md` + `model-routing-and-selection.md`):** Claude Code documents its full auth precedence stack explicitly, plus `/usage`/`/context`/`/status` budgeting surfaces, the spend-denominated `max_budget_usd` already met in the loop chapter (which documents "covers subagents: their spend counts toward the total"), and the three enforcement layers the book keeps separate (SDK-level `max_turns`/`max_budget_usd`, workflow-level, org-level Managed `settings.json` policy).

## Loop, memory, context, and transport

**Loop (VERIFIED, `agent-loop-implementations.md` Section 1):** SDK-verified five-stage while loop (`SystemMessage init` -> `AssistantMessage` -> `execute tools` with hook interception before execution -> repeat as turns -> `ResultMessage` with `success` vs. `error_max_turns`/`error_max_budget_usd`). A turn is one full cycle; "Turns continue until Claude produces output with no tool calls." Tool results append as `UserMessage` (the same append-to-context shape Ch.02 describes, now named). Read-only tools can run concurrently; state-modifying tools (Edit/Write/Bash) run sequentially unless `readOnlyHint` is set. Source caveat: SDK docs are product-surface documentation, not published source -- closing the verification boundary honestly.

**Memory and instructions (VERIFIED, `memory-management.md` Section 1 + `instruction-context-budget.md` Section 1):** CLAUDE.md discovery (Managed/User/Project/Local concatenation, `@path/to/import` at launch, recursion cap four, code-span exclusion), plus the modular `.claude/rules/**/*.md` tier (unscoped loads at launch, `paths:`-frontmatter loads only on matching file read -- not every tool use -- with `project`/`--setting-sources` gating as of v2.1.211, and per-rule brace-expansion budgets 1,000 patterns / 4 MiB). Auto memory (`~/.claude/projects/<project>/memory/` shared across worktrees) with `MEMORY.md`'s hard `200 lines or 25KB` load budget, on-demand topic files via ordinary file tools (not a special primitive), the `CLAUDE_CODE_DISABLE_AUTO_MEMORY`/`autoMemoryEnabled`/`autoMemoryDirectory` controls, and the `PreCompact`-blockable evict-then-summarize compaction where survive-vs-lost is tiered (project-root re-injects; `paths:` rules are lost until re-triggered; skill bodies cap 5,000/25,000). Mid-session edit visibility for the launch-loaded tier is undocumented as a watcher; compaction re-read is the only documented re-load path.

**Context operations (VERIFIED, `context-compression.md` + `caching.md` + `session-persistence.md`):** two-phase evict-then-summarize (with the community name "microcompaction" flagged as unofficial, trigger percentage undocumented beyond the `60% -> 80%` warning-threshold CHANGELOG entry) and thrash guard (three refills -> stop with actionable error). Caching: layer-ordered prefix match, TTL-by-auth-path, subagent/fork behaviour, `ENABLE_PROMPT_CACHING_1H`/`FORCE_PROMPT_CACHING_5M`, `--exclude-dynamic-system-prompt-sections`, Anthropic Messages breakpoint cap + 20-block lookback. Session persistence: plaintext JSONL under `~/.claude/projects/` with `claude --continue`/`--resume`/`--fork-session`/`/branch` and the "each new session starts with a fresh context window" boundary.

**Transport and model selection (VERIFIED, `llm-api-contract.md` + `streaming-and-incremental-rendering.md` + `retries.md` + `model-routing-and-selection.md`):** wire vocabulary `tool_use`/`tool_result` + `stop_reason` + `message_start`..`message_stop` + `content_block_delta` (the Anthropic envelope); streaming reassembly/pacing with the changelog-traced delta-coalescing optimization; retry policy via `CLAUDE_CODE_MAX_RETRIES` (default 10) + `CLAUDE_CODE_RETRY_WATCHDOG`/`API_TIMEOUT_MS` + `fallbackModel` + the retried-vs-not category list and the five flagged changelog fixes; four-tier session-model precedence for routing.

## Coordination, skills, tools, and MCP

**Coordination (VERIFIED, `orchestration.md` + `handoff-mechanism.md` + `fan-out.md` + `inter-agent-messaging.md`):** default **turn-by-turn** orchestration (each turn's model decides the next subagent call from the transcript) vs. **Dynamic workflows** (`agent()`/`pipeline()`, script-held plan with start-order resume, `16-concurrent`/`1,000-total` caps and `/deep-research` as shipped example); **fresh-context subagents** with forks (parent-context, single-use) vs. named/resumeable subagents via `SendMessage` + agent ID, with depth/session/concurrency caps; three fan-out layers (in-conversation caps vs. background sessions with no hard cap vs. Workflow `pipeline()` with 16/1,000 caps); **file-based mailbox** at `~/.claude/teams/{team}/inboxes/{agent}.json` (v2.1.199 collision guard, v2.1.207 validation) with structured `shutdown_request`/`plan_approval_response` messages and the `TeammateIdle`/`TaskCreated`/`TaskCompleted` hook family. Claude Code is the book's clearest real blackboard instance (agent-team shared self-claimed task list) and the clearest consensus instance (`/deep-research` claim-voting), per [multi-agent-coordination-design-space.md](../../references/harnesses/multi-agent-coordination-design-space.md).

**Tools and skills (VERIFIED, `built-in-tools.md` + `built-in-skills.md` + `system-prompt-design-as-craft.md` + `tool-schema-and-interface-design.md`):** the docs-confirmed table with `permission-required` semantics and the `TodoWrite`->`Task*` migration (with model-conditional withholding on Opus 4.8/Sonnet 5/Fable 5/Mythos 5+), three-way `Task` naming overload, Edit three-gate check, and the `strict: true` schema-authoring discipline; bundled skills (`/doctor`, `/code-review`, `/batch`, `/debug`, `/loop`, `/claude-api`, `/verify`, `/run`, `/run-skill-generator`, `/dataviz`, `/design-sync`, `/fewer-permission-prompts`) with `disableBundledSkills`/`skillOverrides` vs. the opt-in `anthropics/skills` marketplace repo and `skill-creator` meta-tool; the system-prompt craft page's guidance on tool-calling phrasing, parallel-tool-call prompting, and the reassembly-before-dispatch discipline (no speculative incomplete-JSON parse).

**MCP (VERIFIED, `mcp-integration.md` Section 1):** config-precedence resolution, discovery walk, tool-search flow, transport and capability-negotiation surface consistent with the anthropic-MCP spec (the page's own verification boundary).

## Observability, packaging, and rendering

**Observability (VERIFIED, `observability-and-self-diagnostics.md` Section 1):** three modelling-consistent layers (debug flags, introspection, traces) plus vendor telemetry -- `--debug`/`--debug=category`/`--debug-file`, `/debug`, `--safe-mode`, `CLAUDE_CONFIG_DIR`, `/heapdump`, `/context`/`/hooks`/`/mcp`/`/status`/`/doctor`, `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA` (`claude_code.interaction`/`llm_request`/`tool`/`tool.execution`/`hook` spans with `traceparent` propagation).

**Packaging (VERIFIED, `packaging-distribution-and-self-update.md` Section 1):** six channels (curl/`irm` installer, Homebrew casks x2, WinGet, signed apt/dnf/apk, npm + `optionalDependencies` postinstall, VS Code extension private-CLI-copy with `autoInstallIdeExtension`), `manifest.json`+GPG/platform-signing integrity, auto-update via `autoUpdatesChannel`/`minimumVersion` (`DISABLE_AUTOUPDATER` vs. `DISABLE_UPDATES`, v2.1.207 streamed-download fix, v2.1.221 launcher fix, plugin-auto-update as distinct).

**Rendering (VERIFIED, `tui-cli-application-architecture.md` Section 1):** Ink-based renderer corroborated indirectly (Ink's README + changelog Yoga/cell-based facts), with a two-path classic-scrollback vs. alt-screen `fullscreen` mode and a 19-context keybindings taxonomy.
